# Weather transport

The backend selects Open-Meteo transport with `WEATHER_OPEN_METEO_TRANSPORT`. Set `apps-script` for the intended production path: Render backend -> signed Google Apps Script bridge -> Open-Meteo. Set `direct` only for explicit local development or rollback. Missing or unknown values return `UNAVAILABLE`; an Apps Script failure never falls back to direct traffic. The browser does not call Open-Meteo or receive the bridge URL or secret.

The Apps Script option uses the backend-only `GOOGLE_DRIVE_APPS_SCRIPT_URL` and `GOOGLE_DRIVE_APPS_SCRIPT_SECRET` settings. The checked-in `scripts/google-drive-apps-script/Code.gs` needs a new owner-run Web App deployment version before selecting this transport in production; this repository change does not deploy it. The weather operation requires Script Property `BRIDGE_SECRET`. Drive upload/read/delete additionally require `FOLDER_ID`. The weather request signs version, operation, timestamp, nonce, and fixed-six-decimal latitude and longitude with HMAC-SHA256. The bridge rejects stale, replayed, tampered, or invalid-coordinate requests. Apps Script fetches only the configured Open-Meteo fields and returns a small status/body/Retry-After result. It does not interpret weather values. Apps Script does not expose a per-request UrlFetchApp timeout option; the backend bridge retains its 30-second request timeout.

The backend remains responsible for `AVAILABLE`/`UNAVAILABLE`, temperature and next-hour precipitation normalization, its ten-minute `AVAILABLE` cache, same-location in-flight deduplication, and global 429 cooldown (60-second default, 300-second cap). Neither transport sends an API key or secret to Open-Meteo. Keep bridge credentials out of frontend settings and logs.
