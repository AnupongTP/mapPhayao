# Parcel photos (local-first)

PostgreSQL/PostGIS remains authoritative for users, parcel ownership, geometry, and business data. It stores no parcel photo records or metadata. Apply `database/migrations/20260924_add_user_display_name.sql` after the existing ownership migrations before enabling the mirror; it adds nullable `app.users.display_name` without changing `picture_url`. Google Drive holds the actual WebP files. Google Sheet is the human-readable business mirror and the photo reference store.

Set these backend-only variables when real Google integration is approved:

- `GOOGLE_MIRROR_ENABLED=true`
- `GOOGLE_SERVICE_ACCOUNT_JSON` (Sheets service-account JSON; never commit it)
- `GOOGLE_SHEETS_SPREADSHEET_ID` = the prepared FarmTech spreadsheet ID
- `GOOGLE_DRIVE_PROVIDER=apps-script` (required for Drive operations; an empty or unknown provider fails closed)
- `GOOGLE_DRIVE_APPS_SCRIPT_URL` = the HTTPS Web App `/exec` URL (backend only)
- `GOOGLE_DRIVE_APPS_SCRIPT_SECRET` = a long random shared signing secret (backend only)

Grant the service account access to the prepared spreadsheet. Sheets continues to use only the service account. Deploy [`scripts/google-drive-apps-script/Code.gs`](../scripts/google-drive-apps-script/Code.gs) as a Google Apps Script Web App, executing as the Google account that owns the prepared FarmTech_Pic folder. Set its Script Properties `BRIDGE_SECRET` to the same secret as the backend and `FOLDER_ID` to that existing folder ID. Deploy the Web App with access allowing server requests (Apps Script may require **Anyone** for unauthenticated HTTP calls); every operation is independently authenticated by the signed request, checked for timestamp and nonce replay, and restricted to that folder. Do not publish the bridge URL or secret in frontend or Netlify settings. Do not test against production until separately approved.

The backend signs version `1` requests for upload/read/delete with HMAC-SHA256, Base64URL without padding. The canonical string is `['1', op || '', String(ts || ''), nonce || '', filename || '', mimeType || '', fileId || '', contentSha256 || ''].join('\n')`. For uploads, `contentSha256` hashes the Base64 *string* of the normalized WebP, not its decoded bytes. The Apps Script verifies the signature, timestamp, nonce, content hash, and folder membership before Drive operations. The signed read operation and authenticated image proxy remain only for rollback compatibility; normal display does not call them. Deletion moves files to Drive trash. No browser talks to Apps Script directly.

For an explicit temporary rollback only, set `GOOGLE_DRIVE_PROVIDER=oauth` and supply backend-only `GOOGLE_DRIVE_OAUTH_CLIENT_ID`, `GOOGLE_DRIVE_OAUTH_CLIENT_SECRET`, `GOOGLE_DRIVE_OAUTH_REFRESH_TOKEN`, and `GOOGLE_DRIVE_PARCEL_IMAGE_FOLDER_ID`. The backend never tries OAuth after an Apps Script error. Missing or invalid selected-provider settings leave Sheets available but image operations return a sanitized 503. Existing tab names and headers remain unchanged. No sharing permissions are changed by the app. Keep `GOOGLE_MIRROR_ENABLED=false` until the owner-run bridge and credentials are ready.

The users sheet stores internal app UUID, verified LINE display name, created_at, updated_at. It never stores LINE user ID or `picture_url`. The parcels tab has the exact A-P contract: `user_id`, `display_name`, `parcel_code`, `parcel_name`, `crop`, `variety`, `planting_date`, `Coordinate`, `geometry`, `area_m2`, `area_rai`, `Image`, `LinkImage`, `note`, `created_at`, `updated_at`. `user_id` is the internal app.users UUID. `display_name` comes from app.users and is human-readable mirror data only, never an authorization identity. Neither LINE user ID nor `picture_url` is exported. The mirror checks the existing A-P header before parcel writes/deletes and reports a mismatch without changing headers.

`Coordinate` is a plain-text WGS84/EPSG:4326 point in latitude, longitude order with six decimal places, for example `19.191926, 99.818955`. The backend derives it from `ST_PointOnSurface` of the persisted EPSG:32647 parcel geometry and transforms that point to EPSG:4326. It is blank only when no valid point is available. `geometry` remains the complete parcel-boundary GeoJSON text in EPSG:4326. The application has no persisted parcel note/remark field, so `note` remains empty. `Image` and `LinkImage` contain aligned JSON arrays of filenames and Drive links in upload order. An empty list is `[]` in both cells. Parcel business updates preserve these arrays. Existing rows gain Coordinate on their next mirror/upsert; no automatic production backfill runs.

Uploads accept decoded JPEG, PNG, WebP and HEIF when supported by the installed Sharp runtime. Each request is limited to 12 MB. The backend auto-orients, shrinks without enlargement to a 1600 px maximum long edge, writes WebP at quality 75, and omits EXIF metadata. Names are generated from parcel code, UTC timestamp and a random suffix. Originals and separate thumbnails are not stored in Drive.

The parcel is created before any image upload. Each photo request verifies ownership in PostgreSQL, normalizes the image, uploads it through signed Apps Script, and appends its filename/link to the same parcel row in Sheet. Parcel detail and image-list reads remain authenticated and ownership-checked before the backend returns trusted `LinkImage` values. The browser displays those images directly from their Sheet `LinkImage` URLs without asking Render or Apps Script to read the image bytes. Drive photo files are intentionally configured as **Anyone with the link → Viewer**: anyone who obtains a `LinkImage` can view that image. The Sheet itself remains private, while uploads and deletions still require LINE authentication, parcel ownership, and the backend-only Apps Script signing secret. The protected image-content endpoint remains for rollback compatibility but is not used for normal display. A failed photo upload does not roll back the parcel; the open save sheet reports the failed count and retries only pending photos. Google business-mirror failures are logged and do not roll back PostgreSQL. Photo failures are returned to the caller. This version has no durable mirror retry/outbox. Drive deletion after parcel deletion is best-effort. If Sheet append fails after Drive upload, the uploaded file is deleted best-effort.

New `LinkImage` entries use `https://drive.usercontent.google.com/download?id=<FILE_ID>&export=view`. Existing Sheet entries in the legacy `https://drive.google.com/uc?export=view&id=<FILE_ID>` format are strictly validated and normalized to the new URL when read; no Sheet migration is required. The browser uses the normalized direct URL for the gallery and fullscreen viewer, not the image-content proxy. Only the two expected Google Drive URL shapes are accepted.

## Local verification

`npm run sandbox:start` uses disposable local PostGIS and fake LINE/Google services. Open `http://127.0.0.1:4173/?liff=1&sandbox-user=a`. Draw a parcel, choose several local images in the naming panel, remove one, analyze, then save. Reopen its saved analysis and check the gallery. Test the same flow without photos, then use User B at `http://127.0.0.1:4173/?liff=1&sandbox-user=b` to check ownership. The fake Google state is available locally at `http://127.0.0.1:3100/__e2e__/google`; no real Google API is called. Stop with `npm run sandbox:stop`, which removes the disposable DB and its images.
